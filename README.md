# Pingoo 🐧

**每天早上，读一份关于你所有网站的简报。**

Pingoo 每天从 Google Analytics 4 和 Google Search Console 同步数据，用规则找出值得注意的变化（飙升、下滑、新外链、排名变化、统计中断……），再让 AI 用大白话讲清楚原因和下一步。为独立开发者设计：一个人、多个网站、没时间研究 GA。

Pingoo 是多用户的 SaaS：任何人用邮箱注册，连接自己的 Google 服务账号；**基础功能免费，AI 功能按积分收费**（卡密充值，按实际用量扣积分）。

> Ping 是检测网络的命令，象征实时掌握网站动态；oo 读起来圆润轻快，呼应小体积、快速部署；Pin-goo 的发音又有点像 penguin——稳重可靠、随时帮你看着流量的小助手。

## 功能

- **全部网站概览**：一句话 AI 简报、合计访客、搜索点击、在线人数、“需要关注”列表、每个网站的小图（图上直接标出原因）。
- **网站详情**：AI 洞察和待办、8 个核心指标、内容表现（飙升 / 下滑 / 常青 / 新冒头 / 入口页 / 待优化）、流量来源（含 AI 助手来源、新外链）、搜索表现（差一点上首页、高曝光低点击、排名下滑）、访客画像、健康检查。
- **AI 诊断**：从异常点、任意一条洞察或单个页面发起，AI 一步步查数据，给出结论、置信度和建议，并展示它查了哪些数据。
- **单页分析**：一个页面的浏览、入口、阅读质量、访客来源和带来点击的全部搜索词。
- **Google 搜索更新标注**：自动读取 Google 搜索状态页，把核心算法更新、垃圾内容更新和搜索故障标在趋势图上，AI 排查原因时也会参考。
- **周报 / 月报**：自动生成，检查上期建议的效果；问答和诊断里“保存到报告”的分析会附在下一期报告里。周一（月报是 1 日）05:00 之后，等各网站同步完上一期最后一天的数据就生成；当天服务没开或生成失败，之后会补上最近的一期。演示网站不参与自动报告。
- **AI 问答**：AI 自己调用工具查 GA 和 Search Console。
- **日期范围和对比**：今天、昨天、7 / 28 / 90 天，或者自选起止日期（最长 366 天）；对比可以选上一期或去年同期（52 周前的同一段，星期几对齐）。去年同期用在核心指标和趋势图上，内容、来源这些明细表格始终和上一期比。
- **提醒可调**：每个网站可以设提醒灵敏度（小网站调高、大网站调低），也可以在设置里按类型关掉不想看的提醒。
- **账号**：只用邮箱注册，初始密码发到邮箱（收到即验证了邮箱）；找回密码、改邮箱、修改密码、退出其他设备、注销账号。注册、登录、找回密码用自己实现的工作量证明（PoW）做人机校验，不依赖第三方验证码。
- **积分**：洞察、诊断、问答、周报月报按 AI 接口返回的实际 token 用量扣积分（服务商价格 × 倍率，1 元 = 100 积分，缓存命中单独计价；个别接口不返回用量时按字数估算，积分明细里会注明）。任务开始前先预扣一笔，结束后按实际用量多退少补（超出预扣的部分照样按实际扣，余额可能暂时为负，充值时先抵扣），失败全额退回；用户可以选模型、打开或关闭“每天自动生成 AI 内容”。
- **套餐**：免费版、基础版、专业版三档（数值在后台可改）。默认：

  | | 免费版 | 基础版 | 专业版 |
  |---|---|---|---|
  | 网站数 | 1 | 5 | 20 |
  | 明细保留（页面、来源、搜索词…） | 30 天 | 90 天 | 180 天 |
  | 每日总数保留（趋势、对比） | 90 天 | 180 天 | 395 天（约 13 个月，可以和去年同期比） |
  | 每月送积分 | 0 | 500 | 2000 |
  | 同步 | 每天 | 每天 + 每 12 小时刷新（只重拉有变化的日子） | 每天 + 每 12 小时刷新（只重拉有变化的日子） |
  | 每日邮件简报 | – | ✓ | ✓ |

  AI 在所有套餐里都按积分原价收费。付费套餐用“套餐卡密”开通（同档续期延长；有效期内换档按价格折算剩余天数），开通或升级时立即送当月积分、之后每 30 天送一次，和充值积分合在一起不过期。到期后功能当天回到免费版，超出名额的网站暂停同步（按网站列表顺序保留前几个，数据不删），数据再保留 7 天，之后超出免费版保留期的删除；到期前 3 天和到期后各发一封提醒。升级后下一次同步会自动把更早的数据补到新套餐的保留期。套餐记在 `users.plan` / `plan_expires_at` 上，以后接在线支付，支付回调里改这两个字段即可。
- **管理后台**：用户和积分调整、停用、直接设置套餐；套餐数值（名称、价格、网站数、保留天数、每月积分、货币符号）；AI 模型（接口、Key、输入 / 输出 / 缓存命中价格、倍率、附加请求参数、默认模型）；生成积分卡密和套餐卡密（下载 CSV，数据库只存哈希）；全站设置（注册赠送积分、暂停注册、全站每日 token 上限）；发信情况和注册熔断状态。
- **广告收益**：网站放了 AdSense（或 Ad Manager、AdMob）并关联到 GA4 后，每天同步时顺带取回广告收入、展示、点击（`ga_daily` 里的三列）和每个页面的广告收入（`ga_daily_ads`，只有放了广告的网站才有行）。网站详情多出“广告收益”一节：收入、每千次浏览收入（RPM）、每日收入图、收入最高的页面、流量大收入低的页面；概览的网站卡片显示广告收入（各网站货币可能不同，不做合计）。两条提醒：广告收益下滑（RPM 掉 30% 以上而流量没怎么变）、高流量低收益页面。AI 洞察、问答、报告都能看到这些数字，并按“流量变化 × RPM 变化”来解释收入。不需要额外授权，用的还是同一个服务账号；没关联 AdSense 的网站不多花一次查询。
- **演示账号**：首页“先看看演示”和顶栏“看演示”进入一个共享的只读账号，里面是 6 个模拟网站（其中两个有广告收益）。演示账号不能调用 AI，但会看到预先写好的示例：全部网站和每个网站的洞察、一份周报、每个网站一份诊断（点图上的异常点就能看到），都按演示数据里的真实数字和提醒写成，并标明“演示示例，不是 AI 生成”。问答保持原样（不能用）。演示数据和示例每天凌晨 3 点刷新到昨天。
- **对外页面**：首页（介绍页，`/`；登录后的概览在 `/overview`）、帮助中心（`/help`：快速上手、一步步连接 GA 和 Search Console、各功能说明、积分怎么算——价格表和“一次大概多少积分”按后台的模型和最近 30 天的实际用量实时算、使用限制、常见问题）、关于、隐私政策、服务条款。
- **出错页**：地址不存在、内容已删除、不是自己的数据、普通用户打开后台，都显示同一个 404 页（没登录也不会先跳登录页）；服务器出错时显示友好的出错页，内部错误只写日志。htmx 局部请求仍然只返回一行文字，前端弹成提示。
- **反馈**：帮助页最后可以直接留言（需要登录，每人每天 5 条），发到管理员的邮箱，回复地址是用户的邮箱，直接回复就行；不单独建表，记在发信记录里。

## 技术栈

Go（标准库 `net/http`）+ PostgreSQL（pgx）+ `html/template` + htmx。AI 接口兼容 OpenAI `/chat/completions`（OpenAI、DeepSeek、通义千问、OpenRouter、Ollama 等，需支持工具调用）。模板和静态文件打包进二进制。

## 快速开始

```bash
cp .env.example .env      # 填上 ADMIN_EMAIL、ADMIN_PASSWORD、APP_SECRET、数据库连接
go run ./cmd/pingoo       # 启动时会自动执行数据库迁移，并用 ADMIN_EMAIL / ADMIN_PASSWORD 建管理员
```

打开 http://localhost:5004 ，用管理员邮箱和密码登录，然后到管理后台：

1. 「设置 → 站点」填站点地址（你的域名），「设置 → 发信」填 SMTP，点“给我发一封测试邮件”确认能发；
2. 「模型」添加至少一个 AI 模型并填上价格；
3. 管理员账号一开始也是 0 积分，自己要用 AI 的话，在「用户」里给自己加积分。

本地开发没有发信服务时，在 `.env` 里加 `MAIL_DRYRUN=true`，注册邮件（含初始密码）会写进日志。

演示数据（首页的“先看看演示”）：

```bash
go run ./cmd/pingoo demo          # 建共享的演示账号，写入 6 个演示网站的模拟数据
go run ./cmd/pingoo demo --reset  # 删除后重新生成
go run ./cmd/pingoo demo --remove # 删除演示账号（后台「设置」里也有按钮）
```

用 Docker（不自带数据库，连接已有的 PostgreSQL；`docker-compose.yml` 默认加入外部网络 `postgres_default`，按你的环境改）：

```bash
cp .env.example .env   # 填好数据库连接、ADMIN_EMAIL、ADMIN_PASSWORD、APP_SECRET
docker build -t pingoo:latest .
docker compose up -d
```

服务器上更新用 `bash build.sh`：拉代码、打包镜像、替换容器。

## 连接 Google

Pingoo 用一个**服务账号**读取数据。服务账号是给程序用的 Google 账号，只能读，GA 和 Search Console 共用这一个。全程大约 10 分钟。

### 第 1 步：新建 Google Cloud 项目

打开 [Google Cloud 控制台](https://console.cloud.google.com/)，点顶部的项目下拉框 →「新建项目」，名字随便取，比如 `pingoo`。

下面用到的三个 API 都可以免费使用（有调用配额），不需要开通结算。

### 第 2 步：启用三个 API

先确认顶部选中的是刚建的项目，然后打开左侧菜单「API 和服务 → 库」，分别搜索并点「启用」：

- **Google Analytics Data API**：读取 GA 报表
- **Google Analytics Admin API**：列出 GA 媒体资源，导入网站时用
- **Google Search Console API**：读取搜索数据

### 第 3 步：创建服务账号

左侧菜单「IAM 和管理 → 服务账号」→「创建服务账号」：

1. 名称随便填，比如 `pingoo`，点「创建并继续」。
2. “向此服务账号授予对项目的访问权限”这一步**直接跳过，不要给任何角色**。Pingoo 只需要读 GA 和 Search Console，这两处的权限在第 5、6 步单独给。
3. 点「完成」。

列表里会出现一个邮箱，形如 `pingoo@你的项目ID.iam.gserviceaccount.com`，后面两步要用到它。

### 第 4 步：下载 JSON 密钥

点进刚创建的服务账号 →「密钥」标签页 →「添加密钥 → 创建新密钥」→ 选 **JSON** →「创建」。浏览器会下载一个 `.json` 文件，这就是钥匙，不要发给别人。

- Google 会提醒“服务账号密钥可能带来安全风险，建议改用工作负载身份联合”。直接继续创建即可。
  - 工作负载身份联合适用于跑在 Google Cloud、AWS、Azure、Kubernetes、GitHub Actions 上的程序，部署在自己的服务器或电脑上用不了。
  - 按本文配置，密钥泄露的影响也很有限，见下面的「密钥安全」。
- 如果出现的是报错“已停用服务账号密钥创建”（不是提醒），说明这个 Google 账号属于某个组织，组织策略禁止创建密钥，需要找组织管理员放开。个人 Gmail 账号一般没有这个限制。

### 第 5 步：在 Google Analytics 里授权

打开 [Google Analytics](https://analytics.google.com/)，点左下角的齿轮「管理」：

- **推荐在账号这一层加**：「账号设置 → 账号访问权限管理」→ 右上角「+」→「添加用户」。
  1. 填第 3 步的邮箱。
  2. 取消勾选「通过电子邮件通知新用户」。
  3. 角色选**查看者**，点「添加」。

  这样这个账号下所有的媒体资源都能读到，以后新建的也会自动包含。
- **只想给部分网站**：在「媒体资源设置 → 媒体资源访问权限管理」里逐个添加，步骤相同。
- 你有多个 GA 账号的话，每个账号都要加一次。

### 第 6 步：在 Search Console 里授权

打开 [Search Console](https://search.google.com/search-console)。**每个网站都要做一次**：

左上角选中网站 →「设置 → 用户和权限 → 添加用户」→ 填同一个邮箱 → 权限选**受限** →「添加」。

- 需要用这个网站的“所有者”身份操作。如果「添加用户」按钮是灰的，说明你当前登录的账号不是所有者。
- 网域资源（`sc-domain:example.com`）和网址前缀资源（`https://example.com/`）都支持。

### 第 7 步：把密钥交给 Pingoo

设置 →「连接 → Google 服务账号」→ 上传 JSON 文件（或粘贴内容）。密钥会用 `.env` 里的 `APP_SECRET` 加密后存进数据库，每个用户的密钥只用来读他自己的网站。

### 第 8 步：测试连接

设置 →「连接」→「测试连接」。三项都显示正常就说明配好了：

- Google Analytics Admin API：可以看到 N 个 GA4 媒体资源
- Google Analytics Data API：可以读取报表数据
- Search Console API：可以访问 N 个网站

### 第 9 步：导入网站

设置 →「网站」→「导入网站」：

- 弹窗会列出服务账号能看到的所有 GA4 媒体资源，并按域名自动配好对应的 Search Console 网站。配错或没配上的，可以在下拉框里手动选。
- 勾选要导入的网站，点「导入」。
- 导入后会在后台回填历史数据：页面、来源、搜索词等明细 90 天，每日总数约 16 个月（用来和去年同期比）。每个网站一般一两分钟，流量大的网站会久一些。进度可以在「同步与用量」里看到。

建议导入后给每个网站点「编辑」，写一段“给 AI 的背景”：网站是做什么的、读者是谁、你最在意什么。AI 的洞察和建议会更贴切。

### 常见问题

| 现象 | 原因和解决办法 |
|---|---|
| 测试连接提示某个 API “has not been used in project … or it is disabled” | 第 2 步漏启用了这个 API，或者启用在了别的项目里。启用后等一两分钟再试 |
| 能看到 0 个 GA4 媒体资源 | 第 5 步没做，或者加在了别的 GA 账号下。旧版 Universal Analytics 媒体资源不支持 |
| Search Console 能访问 0 个网站 | 第 6 步没做，或者没用所有者身份添加 |
| 导入时某个网站没自动配上 Search Console | Search Console 里的网址和 GA 里的域名对不上（例如一个带 www、一个不带），在导入弹窗或网站「编辑」里手动选 |
| 某个网站只有 GA 数据，没有搜索数据 | 这个网站还没在 Search Console 验证，或者没给服务账号加权限 |
| 担心密钥泄露 / 已经泄露 | 在 Cloud 控制台「服务账号 → 密钥」里删掉这把密钥，它会立刻失效；再新建一把替换即可，GA 和 Search Console 的授权不用重做 |

### 密钥安全

按上面的步骤配置，即使密钥泄露，影响也很有限：

- 服务账号在 Google Cloud 项目里没有任何角色，拿到密钥的人建不了资源，也花不了你的钱。
- 它在 GA 里是“查看者”、在 Search Console 里是“受限”，最多只能**读**你授权的那几个网站的数据，改不了任何东西。
- 它和你的 Google 账号是分开的，泄露了也登录不了你的账号。
- 发现泄露就删掉这把密钥，它会立刻失效。

## 配置

`.env` 里只放程序启动前就要用到、或者保护数据库本身的配置，见 [.env.example](.env.example)：数据库连接、`APP_SECRET`、端口、`TRUSTED_PROXIES`，以及第一次启动用的管理员邮箱和密码。

其余都在管理后台里改，改了马上生效、不用重启：

- **站点**：站点地址（邮件里的链接用它；以 https 开头时登录 cookie 自动加上 Secure）、默认时区。
- **发信**：SMTP 服务器、端口、用户名、密码（加密保存）、发件地址和名称、24 小时发信上限，可以给自己发测试邮件。
- **AI 模型**和**积分规则**；Google 服务账号是每个用户在自己的设置里上传。

管理后台里和运行成本有关的开关：

- **全站每日 token 上限**：所有用户合计，到了之后当天暂停 AI，第二天自动恢复。默认不限。
- **数据保留**：按网站主人的套餐（见上面的表，多留 2 天余量）。过期的行每天真正 `DELETE`，删完对这几张表做一次 `VACUUM (ANALYZE)`；明细表的 autovacuum 阈值调到 2%（默认 20%），删掉的空位很快就给新数据用。“需要关注”的提醒按最长的明细保留期清理；同步记录、发信记录留 90 天，AI 消耗明细留 400 天，旧洞察会自动清理（充值、套餐记录一直保留）。回填范围和套餐保留期一致，不会回填了第二天又删掉。
- **整理表空间**：重新同步、删除过期数据会在表文件里留下空位，数据库会重复利用，但不会把文件缩小。每天凌晨 3 点（后台“默认时区”）自动检查一次：空位超过一半、并且超过 16 MB 的表才用 `VACUUM FULL` 整理（整理时这张表会锁几秒到几十秒，所以放在半夜、只碰被撑大的表）。也可以随时手动运行 `pingoo compact` 整理全部。开发库实测：同步数据表从 930 MB 降到 177 MB，数据一行不少。
- **演示数据**：每天凌晨 3 点检查，过时了（最新一天早于昨天）就重新生成到昨天；演示账号不变，正在看演示的访客不会被登出。首页正文和顶栏的“看演示”只对没登录的访客显示。
- **购买链接**：后台「套餐」里填购买套餐卡密的地址（发卡网站、店铺或支付页），首页价格卡片的“购买”按钮、设置页和到期提醒邮件都会链接到它。
- **注册赠送积分**（默认 0）、**暂停注册**。

### 人机校验和发信限额

- 注册、登录、找回密码要求浏览器先算一个工作量证明：找一个 nonce，使 SHA-256(salt + ":" + nonce) 的前 20 位为 0（手机约 1 秒，在 Web Worker 里用纯 JS 计算）。挑战带签名（密钥由 APP_SECRET 派生，重启前打开的页面重启后照样能提交），30 分钟内有效、只能用一次（已用记录在内存里，重启前用过的挑战重启后还能再用一次，登录锁定和发信限额照样生效）、签发后不足 2 秒提交视为脚本。表单里还有一个移到屏幕外的陷阱输入框。
- 注册邮件：同一邮箱每天 3 封、同一 IP 每天 10 封；每小时超过 50 封时注册页的难度提高到 23 位（全站熔断），只有达到后台设置的 24 小时发信上限才真正暂停注册。找回密码：同一邮箱每分钟 1 封、每天 5 封（在查库之前判断，不暴露邮箱是否注册）。改邮箱验证码：同一用户每分钟 1 封、每天 5 封，需要原密码。
- 收件域名必须有 MX 记录（域名不存在、没有 MX、Null MX、单段域名都拒绝；DNS 超时放行）。注册、改邮箱时当场提示，所有邮件发送前也会再检查一次。
- 找回密码另有来源限制：同一 IP 每天 10 次（换着邮箱填也算），不然能给所有注册用户发信、耗光全站发信额度。改邮箱验证码另有收件人限制：同一个新邮箱每天最多 3 封（多个账号轮流轰炸同一个邮箱也不行）。
- 按 IP 的限额（注册、找回密码、登录锁定、进入演示）对 IPv6 按 /64 网段计：一个 /64 里的地址可以随便换，按单个地址限额等于没限。
- 后台的“24 小时发信上限”对所有邮件生效（注册、找回密码、验证码、反馈、测试邮件），在发信的唯一出口里把关，哪个入口被刷都超不过它。
- “已用挑战”、登录失败次数、进入演示的次数都在内存里，所以只支持单实例部署。卡密输错的次数存在数据库里（每人每小时 10 次），重启不会清零；卡密和积分本身一直在数据库里，重启不影响兑换。

### 防止刷 AI 和绕过计费

- 余额要够这类任务的预扣额才能开始；预扣用一条带条件的 `UPDATE` 完成，并发点很多次也只会成功余额够的那几次。
- AI 每一轮都把整段对话重新发一遍，用户能控制的输入都有上限：问答每个问题最多 2000 字，历史只带最近 20 条、每条最多 3000 字；诊断的标题 120 字、问题 1000 字；网站的“给 AI 的背景” 1000 字；待办 300 / 500 字。工具查询结果每次最多 8000 字。
- 实际用量超过预扣时照样按实际扣（余额可能为负，充值先抵扣，余额不为正时不能用 AI）。为了不让余额被扣成很大的负数：用量到了“预扣 + 剩余余额”的八成时，AI 不再查数据、用已经查到的数据直接给结论。余额充足的用户碰不到这条（任务本身最多 10 轮），分析不会被提前打断；免费模型（价格为 0）不受影响。
- 后台扣积分最多扣到 0；余额已经是负数时不会再扣，也不会反而加上。
- “新用户赠送积分”会招来用临时邮箱批量注册的人，建议只给够试一两次的量；全站每日 token 上限可以兜底。
- 省 AI 费用：系统提示把不变的规则放在最前面、日期和网站列表放后面，不同任务、不同用户开头相同，更容易命中服务商的提示缓存。推理模型的“思考”按输出计费（实测诊断的输出 token 是输入的 1.9 倍），可以在模型的“附加请求参数”里加 `{"reasoning_effort": "low"}`（OpenAI o 系列、Gemini、Grok 等）或 `{"enable_thinking": false}`（通义千问），改完用“测试”确认回答正常。

### 演示账号

- 共享的只读账号：所有改动类请求（POST）都会被拦下；不能用 AI（预扣时直接拒绝演示账号）；不能用密码登录、找回密码或改邮箱。
- 没有设置页：设置页里有“已登录的设备”（会暴露其他访客的 IP），导入网站会调 Google 接口，演示账号打开 `/settings` 下的任何地址都会回到概览。
- 已经在演示里再点“看演示”不会重复建会话；同一来源每小时最多进入 20 次，防止脚本刷会话表；演示会话 6 小时过期，过期的会话每 6 小时清理一次。

### 其他

- 服务账号密钥是用户上传的，里面的 `token_uri` 可以被改成任意地址；换取令牌时固定用 Google 的地址，不然服务器会替用户去请求内网或云厂商的元数据接口（SSRF）。

放到公网时要注意：

- 后台的站点地址一定要改成你的域名：邮件里的链接用它（不能从请求的 Host 头取，Host 头可以被伪造）。还是 localhost 时后台会提醒。
- 同一来源连续输错密码 5 次会锁定 15 分钟；所有来源合计每分钟最多 300 次失败，超过后暂时拒绝登录。
- 前面有反向代理（Nginx、Caddy 等）时，在 `TRUSTED_PROXIES` 里填代理的 IP 或网段，并让代理把 `Host` 和 `X-Forwarded-For` 原样转给 Pingoo。不填的话所有访客看起来都来自代理的 IP，一个人输错密码会把所有人一起锁住。没有代理时不要填。
- 最前面是 Cloudflare 这类 CDN、中间还隔着几层代理时，可以设 `REAL_IP_HEADER=CF-Connecting-IP`，程序直接读 CDN 写入的访客 IP，`TRUSTED_PROXIES` 只填紧挨着 Pingoo 的那一层。源站要只接受来自 CDN 的流量，否则绕过 CDN 直连的人可以伪造这个头。
- Amazon SES 新账户在“沙箱”里只能发给验证过的地址、每天 200 封，正式上线前要在 SES 控制台申请生产权限，并把后台的发信上限改成你的发送配额。

## 数据怎么来的

- 最多 3 个网站同时同步，新网站的首次回填不会挡住其他网站。
- GA 和 Search Console 的每日总数（访客、会话、点击…）回填约 16 个月，用来和去年同期对比；页面、来源、搜索词等明细只回填 90 天（保留期 92 天）。
- 每天当地时间 04:00 后同步“昨天”的数据，并重新拉取 GA 最近 3 天、Search Console 最近 5 天（这些数据还会被 Google 修正）。
- 访客数不能跨天相加，所以“近 28 天访客”这类去重人数会实时查询 GA（每天同步后提前算好并缓存，到下一次同步为止）；每日表只用来画趋势。
- 大网站的长尾会裁掉：某一天的页面（或入口页）超过 2,000 行时，只保留当天前 2,000 名和其余浏览 ≥ 3 次的行。只被看过一两次的页面占了九成行数，却几乎不影响分析。网站总数（访客、浏览量）不受影响。
- GA 数据量超过表格上限时会把放不下的小项合并成“(other)”，这些行不参与页面排行；标题跟着搜索词变的页面（如 /search）只显示路径。
- 规则引擎算出数字和信号，AI 只负责解释原因和给建议；AI 的推测会标注出来。
- AI 洞察存在数据库里，刷新页面不会重新调用 AI。打开了“每天自动生成 AI 内容”的用户，每天同步后自动生成各网站“近 7 天”的洞察（20 小时内已有就跳过）；其他情况都要点“生成洞察”才生成，不会在用户不知情时花积分。生成时直接附上核心数字、渠道、页面涨跌和搜索词，AI 最多再查 6 次数据（深挖交给诊断）。
- 每个用户的数据相互隔离：所有查询都按当前登录用户过滤，AI 调用工具时也只能查自己的网站；表单里改过的网站 ID 不会让记录挂到别人的网站下。
- AI 模型建议用一个固定的、支持工具调用的模型。免费模型或“自动路由”每次可能换模型，速度和准确度都不稳定（问答可能要几分钟）。

## 目录

```
cmd/pingoo          入口（serve / migrate / demo）
internal/config     读取 .env
internal/db         连接与迁移（migrations/*.sql）
internal/store      用户、积分、模型、卡密、设置、网站、信号、报告、对话等读写
internal/google     GA Data / Admin API、Search Console API（REST）
internal/syncer     每日同步与回填
internal/metrics    页面需要的各种查询
internal/signals    规则引擎（需要关注）
internal/llm        OpenAI 兼容客户端 + 工具调用循环
internal/agent      洞察、诊断、报告、问答
internal/scheduler  定时任务
internal/pow        人机校验（工作量证明）
internal/mail       发信（SMTP）和收件域名 MX 检查
internal/web        路由、处理函数、模板函数
web/                模板与静态文件
```

## 测试

```bash
make test       # 单元测试，不需要数据库
make test-db    # 加上连数据库的集成测试
```

`make test-db` 用 `.env` 里配置的数据库：每个测试包在里面建一个临时 schema（`pingoo_test_xxx`），跑完迁移和测试后整个删掉，不会碰已有的表。也可以用 `PINGOO_TEST_DATABASE_URL=postgres://… go test ./...` 指定另一个库。
